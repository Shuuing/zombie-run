# 폭포 / 호수 (플랫 셀 스타일 물)

레퍼런스는 손으로 그린 듯한 셀 페인팅 물. 에셋스토어의 준-사실적 물(Stylized Water 계열)이
아니라 **굴절·반사·화면공간 포말을 전혀 쓰지 않는** 쪽으로 만들었다.

## 재생성 순서

```
1) Blender 로 지형 FBX           ArtSource/blender/make_waterfall.py
2) Tools ▸ 좀비 오버런 ▸ 물 디오라마 셋업     FBX + 머티리얼 + 충돌 → 프리팹
3) Tools ▸ 좀비 오버런 ▸ 필드 생성 (챕터 01)   필드 씬에 배치 + 물 위 프롭 금지
4) Tools ▸ 좀비 오버런 ▸ 프로토타입 씬 생성
```

```
"E:/Program Files/Blender Foundation/Blender 4.4/blender.exe" --background --factory-startup \
  --python ArtSource/blender/make_waterfall.py
```

**Blender 는 C 드라이브가 아니라 `E:\Program Files\Blender Foundation\Blender 4.4\` 에 있다.**
스크립트는 결정론적이다 (`random.seed(20260902)`).

## 왜 이 방식인가

`URP-Balanced` / `URP-Performant` 둘 다 `RequireDepthTexture = False`, `RequireOpaqueTexture = False`다.
깊이 기반 물(얕은/깊은 그라데이션, 교차 포말)과 굴절은 이 둘을 켜야 하는데 각각 **뎁스 프리패스**
(현재 렌더러 80여 개를 한 번 더 그림)와 **전체화면 컬러 복사**를 요구한다.
게다가 카메라가 pitch 58° 탑다운이라 굴절·반사가 거의 보이지 않는다 — 비용은 다 내고 효과는 안 보인다.

그래서 필요한 정보를 **메시 정점 컬러에 구워서** 쓴다. 텍스처는 0장이고 물결·포말은 셰이더 안에서
값 노이즈로 만든다.

| 채널 | 의미 |
|---|---|
| R | 깊이 — 0(물가) ~ 1(중앙). 폭포에서는 시트 가장자리 감쇠 |
| G | 포말 마스크 — 1(물가/낙하지점) ~ 0(안쪽) |
| B | 흐름 좌표 — 0(위) ~ 1(아래). 폭포 낙하 진행도 |

## 지형 (Blender 생성)

기존 필드가 완전히 평면(모든 Ground 가 y=0.00~0.03)이라 지형을 파낼 수 없다. 그래서 레퍼런스처럼
**바닥 위에 올려놓는 암반 디오라마**로 만들었다. 기존 Ground 평면을 건드리지 않는다.

```
LAKE_X, LAKE_Z = 4.4, 4.6     수면 반경 (둥근 사각형, superellipse 지수 3)
WATER_Y        = 0.55         수면 높이
RIM_TOP        = 0.78         암반 림 윗면
BED_SHORE/DEEP = 0.45 / 0.08  호수 바닥 (물가 얕음 → 중앙 깊음)
RIM_W          = 1.15         림 두께
CLIFF_Z0/D/H   = 4.9 / 2.6 / 4.0
SPILL_W/Y      = 1.25 / 2.55  물이 넘어오는 홈 (반폭 / 높이)
```

파트별 트라이앵글: Lake_Bed 648 / Rock_Rim 336 / Rock_Cliff 160 / Water_Lake 968 /
Water_Fall 320 / Water_Splash 240 — **총 2,672**.

### `to_disk` — 물 시트를 둥근 사각형으로 접는다

`build_lake` / `build_bed` / `build_splash` 는 사각 격자를 만든다. 처음엔 superellipse 를
**정점 컬러(깊이·포말)에만** 썼고 외곽선은 사각형인 채로 뒀는데, 그러면 **물 시트의 네 모서리가
둥근 암반 림 밖으로 삐져나와 잔디 위에 반투명 사각형이 깔린다.** (한동안 "절벽 그림자가 잔디에
밝은 사각형으로 보인다"고 오진했던 현상의 실제 원인이 이것이다.)

`to_disk(u, v)` 가 격자를 접는다. 격자 경계 `max(|u|,|v|) = 1` 이 정확히 superellipse 경계에
앉도록 `s = max(|u|,|v|) / (|u|³+|v|³)^(1/3)` 를 곱한다. 접은 뒤의 superellipse 노름은
원래의 체비셰프 노름과 같으므로, **깊이·포말은 `f = 1 - max(|u|,|v|)` 로 그대로 계산하면 된다.**
격자가 찌그러지지 않고 트라이앵글 수도 그대로다.

### Blender → Unity 에서 두 번 막혔던 지점

- **1/100 스케일 + 자식에 회전 89.98°가 남는다.** 익스포트 플래그를
  `apply_scale_options='FBX_SCALE_UNITS'` + `bake_space_transform=True` 로 해야 정점에 구워지고
  오브젝트 트랜스폼이 항등이 된다. Unity 임포터는 `useFileScale=true, globalScale=1`.
- **UV 를 월드 XY 로 깔면 절벽·림 같은 수직면에서 줄무늬가 생긴다.** 면의 지배 축을 골라
  투영하는 삼평면(triplanar) UV 로 바꿨다 (스케일 0.34/유닛).
- **축이 뒤집힌다.** Blender 에서 +Y(절벽 쪽)로 만든 것이 Unity 로 오면 **로컬 -Z** 가 된다.
  그래서 필드에 놓을 때 Y 180° 회전이 필요하다 (아래 참조).

계산해 굽고 FBX 로 내보낸다. 정점을 손으로 칠할 필요가 없다.

```
"E:/Program Files/Blender Foundation/Blender 4.4/blender.exe" --background --factory-startup   --python ArtSource/blender/bake_water_vcol.py
```

스크립트 상단 `PARTS` 에 어느 오브젝트/머티리얼 인덱스가 어느 물인지만 적으면 된다.

| 항목 | 의미 |
|---|---|
| `kind` | `FLAT`(호수·강) / `FALL`(수직 낙하 시트) |
| `cuts` | 세분화 횟수. 형태는 안 바뀐다 |
| `open_ends` | 흐름 축 양 끝 단면을 물가로 치지 않는다 (강이 맵 밖으로 이어지는 경우) |
| `foam` / `depth` | 미터 단위. 물가 포말 띠 폭 / 깊이 1 에 도달하는 거리 |

### 물가를 어떻게 찾나

**메시의 열린 테두리만으로는 안 된다.** 호수를 "평면이 지형을 뚫고 들어간" 형태로 만들면
테두리가 지형 속에 파묻혀 있어 아무 의미가 없다. 그래서 지형에 아래로 레이캐스트해 수심을 재고,
**테두리 OR 수심<=0** 인 정점을 물가로 잡은 뒤 에지를 따라 다익스트라로 실제 미터 거리를 잰다.

반대로 강처럼 **수면이 지형 바닥에 딱 붙어 있으면** 수심 판정이 전 정점을 물가로 만들어 버린다.
그때는 자동으로 열린 테두리(둑)만 쓴다 (`use_terrain` 판정, 잠긴 정점이 5% 미만이면 끔).

### 실제로 걸렸던 함정 3개

1. **해상도가 곧 그라데이션 품질이다.** 정점 컬러는 정점에서만 값을 가지므로,
   폭이 쿼드 1칸인 강은 안쪽 정점이 없어 깊이가 **절대** 안 생긴다(전면 흰색). 폭포도 3폴리면
   정점이 전부 좌우 끝이라 가장자리 감쇠가 전부 0. 그래서 굽기 전에 세분화한다.
2. **감마.** FBX 익스포트가 `colors_type='SRGB'` 로 linear->sRGB 변환을 한 번 건다.
   보정 없이 구우면 B=0.50 이 0.74 로, R=0.15 가 0.42 로 부풀어 **폭포가 통째로 하얘진다.**
   `srgb_to_linear()` 로 미리 역변환해 상쇄한다.
3. **포말 폭은 수면 폭에 맞춰야 한다.** 폭 1.5m 인 강에 포말 0.5m 를 주면 양쪽 합쳐 1.0m 라
   강이 거의 전부 하얘진다. `depth` 도 반폭보다 크면 깊은 색이 아예 안 나온다.
   강은 foam 0.18 / depth 0.60, 호수는 0.50 / 1.50 이 적당했다.

### 메시 쪽 요구사항

- **수면을 지형과 별도 오브젝트(또는 별도 머티리얼 ID)로 분리할 것.**
- 3ds Max 에서 내보낼 때 **FBX 익스포트 옵션의 Vertex Colors 를 켤 것** — 안 켜면 조용히 빠진다.
  (이 스크립트로 구우면 Blender 가 다시 내보내므로 원본에는 정점 컬러가 없어도 된다.)
- UV 는 스크립트가 다시 깐다. 수평면은 월드 XY 평면 투영 0.22/유닛, 폭포는 가로 0..1 정규화.

## 텍스처 교체 (선택)

기본은 텍스처 0장이지만, 손으로 그린 무늬를 쓰고 싶으면 슬롯 두 개가 있다.
**둘 다 기본은 꺼져 있고, 꺼져 있으면 샘플러가 아예 컴파일되지 않아 예전과 완전히 같은 비용이다**
(`shader_feature_local_fragment`). 켜는 순간 픽셀당 텍스처 페치가 1회 붙는다 — 모바일에서
텍스처를 안 쓰기로 한 게 원래 설계 의도였으니, 켤 거면 그 값을 하는지 보고 결정할 것.

### 1. Pattern Texture — 무늬 자체를 갈아끼운다

물결 선(호수)과 세로 줄무늬(폭포)를 만드는 **값 노이즈를 텍스처로 대체**한다.

| 채널 | 쓰임 |
|---|---|
| **R** | 호수 물결 / 폭포 줄무늬 |
| **G** | 물가 포말 흔들림 |
| B, A | 안 씀 |

회색조 한 장이면 R=G 라 그대로 동작한다.

- **반드시 이음매 없는(seamless) 텍스처여야 한다.** 스크롤하며 반복 샘플한다.
- **대비를 0~1 로 꽉 채울 것.** 물결 선은 `smoothstep(0.52 ± _RippleWidth, ...)` 로 좁은 대역만
  남겨 만든다. 텍스처 값이 0.35~0.66 같은 좁은 범위면 그 대역에 걸리는 픽셀이 없어 **물결이
  통째로 사라진다** (실제로 처음 구운 예제가 이랬다).
- UV 는 절차적 노이즈와 같은 좌표를 쓰므로 `_RippleScale` / `_RippleStretch` / `_FlowSpeed` /
  `_RippleSpeed` 가 그대로 먹는다. 텍스처의 Tiling 은 그 위에 한 번 더 곱해진다.
- 임포터: **sRGB 끌 것** (색이 아니라 무늬 값이다), Wrap = Repeat.

예제: `T_Water_Pattern_Example.png` (256², 4 노이즈 유닛/타일).
`M_Water_Lake` 슬롯에 **이미 꽂혀 있고 토글만 꺼져 있다** — Inspector 에서
`Use Pattern Texture` 만 체크하면 바로 보인다. 이 예제 기준 Tiling **0.25** 가 절차적 노이즈와 1:1.
직접 만들 때 참고할 채널 배치 견본이기도 하다.

### 2. Surface Texture — 물색 위에 직접 입힌다

물색(깊이 계단) 위에 얹는다. **포말·물결 선보다 먼저** 적용되므로 하얀 포말은 무늬에 먹히지 않는다.

| 슬라이더 | 의미 |
|---|---|
| `Surface Detail (x2 multiply)` | 회색조 디테일용. **중간회색 0.5 에서 변화 없음** — 밝은 곳은 밝히고 어두운 곳은 어둡게 |
| `Surface Tint (replace color)` | 색이 칠해진 물 텍스처를 그대로 얹고 싶을 때 |
| `Surface Scroll By Flow` | `_FlowDir`/`_FlowSpeed` 를 따라 흐르게 할지 |

Tiling/Offset 은 메시 UV 기준이다. 물 메시 UV 는 **0.22/유닛**이라 Tiling 1 이면 한 타일이
약 4.5m 다.

## 움직이는 물가 (선택)

레퍼런스처럼 **물가 선 자체가 밀려왔다 빠지게** 한다. 무늬만 흐르는 것(`_FoamWobble`)과 달리
물의 실루엣이 움직인다. 키프레임 애니메이션이 아니라 전부 셰이더다.

### `Animate Waterline` (`BCM_WATER_SHORELINE`) — 물가 선을 깎는다

정점 컬러 R(깊이)을 시간에 따라 오르내리는 임계값으로 잘라낸다. 포말도 그 선을 따라간다.

| 프로퍼티 | 기본 | 의미 |
|---|---:|---|
| `Carve Depth` | 0.12 | 물이 최대로 빠지는 양 (깊이 단위). **물 메시가 의도한 물가보다 이만큼 바깥으로 더 나와 있어야 한다** |
| `Edge Softness` | 0.04 | 물가 선의 흐림. 0 에 가까울수록 셀 룩 |
| `Lap Foam Width` | 0.10 | 움직이는 선을 따라다니는 포말 띠 폭 |
| `Wave Scale` | 3 | 물가 굴곡의 공간 주파수 (메시 UV 기준) |
| `Wave Speed` | 0.5 | |
| `Rhythm` | 0.5 | **0 = 노이즈만("흘러간다"), 1 = 사인만("전체가 한꺼번에 뛴다")**. 섞어야 파도가 치는 것처럼 읽힌다 |

- **깊이가 0 인 가장자리가 실제 물가보다 바깥에 있어야 한다.** 깎아낼 여유가 없으면 아무 일도
  안 일어난다. Blender 쪽에서 수면 메시를 의도한 물가보다 조금 더 넓게 뽑을 것.
- `Lap Foam Width` 를 0 으로 두면 **물이 빠진 자리에 정점 마스크 포말만 남아 공중에 뜬다.**
  포말은 반드시 움직이는 선을 따라가야 한다 (기본값이 그렇게 돼 있다).
- 기존 정점 마스크 포말과 `max()` 로 합쳐지므로, 폭포 낙하 지점처럼 구워둔 포말은 그대로 남는다.

검증: `Carve Depth 0.35` 로 켜니 두꺼운 정점 포말 띠가 사라지고 구불구불한 얇은 물가 선으로
바뀌었고, 13초 간격 두 프레임에서 좌측 물가선이 x 144→140 / 141→133 / 145→135 로 이동
(물 픽셀 +2.7%). 실제로 선이 들락거린다.

### `Vertex Waves` (`BCM_WATER_WAVES`) — 수면을 위아래로 흔든다

어긋난 사인 두 개를 겹쳐 정점을 올린다. **깊이(R)로 감쇠하므로 물가는 거의 안 움직인다** —
안 그러면 물가가 지형 밖으로 삐져나온다. 폭포 모드에서는 자동으로 꺼진다.

| 프로퍼티 | 기본 | 비고 |
|---|---:|---|
| `Height` | 0.06 | pitch 58° 탑다운에서는 잘 안 보인다. 낮은 각도 컷이 있을 때 값을 한다 |
| `Scale` | 1.5 | |
| `Speed` | 1.2 | |

물가 선을 움직이는 건 **Waterline 쪽**이다. 지형에 얕은 물가가 있어도 이 셰이더는 깊이 텍스처를
안 쓰므로 수면 높이 변화가 물가 선을 밀지 않는다 — 둘은 독립적으로 켜고 끈다.

### 왜 우리 호수에서는 잘 안 보이나

현재 호수는 물가가 잔디에 직접 닿지 않고 **암반 림 안쪽 벽에 막혀 있다.** 물가 선이 움직여도
돌벽에 가려 몇 cm 만 보인다. 파도치는 물가를 보려면 림을 낮추거나 한쪽을 모래사장처럼 완만하게
튼 지형이 필요하다. 그래서 **두 기능 모두 기본은 꺼져 있다** (M_Water_Lake 는 어제 튜닝한 룩 그대로).

### 켤 때 주의 — 토글은 float 만으로 안 켜진다

`[Toggle(KEYWORD)]` 이라 Inspector 체크박스는 float 과 키워드를 같이 바꾸지만,
**코드로 `SetFloat` 만 하면 무늬가 안 나온다.** `EnableKeyword`/`DisableKeyword` 도 같이 할 것.
`WaterSetup.FixKeywords()` 가 셋업 때마다 float 값을 보고 네 토글
(`BCM_WATER_FALL` / `BCM_WATER_LIGHTTINT` / `BCM_WATER_PATTERNTEX` / `BCM_WATER_SURFACETEX` /
`BCM_WATER_SHORELINE` / `BCM_WATER_WAVES`)을 맞춰준다.

**에디터에서 물이 멈춰 보이면** Scene 뷰 Effects 드롭다운의 **Animated Materials 가 꺼져 있는지**
먼저 볼 것. 꺼져 있으면 `_Time` 이 안 흘러 모든 물 애니메이션이 정지한다 (셰이더 문제가 아니다).

### `quantize()` 의 1.0 함정 (수정됨)

```hlsl
// 틀린 버전 — v == 1.0 이면 floor(1*n)/(n-1) = n/(n-1) > 1
return floor(saturate(v) * n) / (n - 1.0);
```

이 값이 `lerp(_ShallowColor, _DeepColor, dq)` 에 들어가면 **_DeepColor 를 넘어서 외삽**된다.
v = 0.9999 는 정상적으로 1.0 이 나오므로, **넓은 면이 깊이 정확히 1.0 으로 구워져 있으면
보간·반올림에 따라 픽셀마다 1.0 과 1.333 을 오가며 하드한 줄무늬가 생긴다.**

강에서 실제로 났다. 물결·포말·글린트를 전부 끄고 알파를 1 로 올려도 남았고, shallow 와 deep 을
같은 색으로 만들었을 때만 사라졌다(외삽해도 같은 색이니까) — 그게 결정적 단서였다.
호수는 깊이가 정확히 1.0 인 정점이 중앙 몇 개뿐이라 티가 안 났을 뿐 같은 버그였다.

```hlsl
return min(floor(saturate(v) * n), n - 1.0) / (n - 1.0);
```

### 노이즈 격자 주기 (`BCM_NOISE_PERIOD`)

`hash21` 이 격자 좌표를 128 주기로 감는다. 시간 스크롤이 누적되면 노이즈 좌표가 수천까지
커지는데, 그대로 456.21 을 곱하면 float 유효자리를 넘겨 `frac()` 이 뭉개진다.
`vnoise` 가 i 와 i+1 을 같이 보므로 경계에서도 정확히 이어진다 — 128 유닛(약 64m)마다
반복될 뿐이라 화면에서는 안 보인다.

### 렌더 큐 2600

캐릭터 발밑 블롭 그림자가 **2450**에 있다. 물을 일반 Transparent(3000)로 두면 순서는 같지만,
2600으로 명시해 물이 그림자보다 뒤에 그려지고(물속 그림자는 물빛에 잠기는 게 맞다) 이후 추가될
파티클/이펙트가 물 위에 오게 했다.

## 머티리얼

`M_Water_Lake` 튜닝값 — 처음엔 물결이 대리석 무늬, 물가 포말이 케이크 프로스팅처럼 보였다.

| 프로퍼티 | 값 | 왜 |
|---|---:|---|
| `_RippleScale` | 13 | 낮으면(9 이하) 선이 아니라 커다란 얼룩이 된다 |
| `_RippleWidth` | 0.028 | 굵으면 대리석 무늬 |
| `_RippleAmount` | 0.15 | |
| `_RippleStretch` | 3 | 늘려야 얼룩이 아니라 붓 자국처럼 읽힌다 |
| `_FoamWidth` | 0.16 | 0.22 는 두꺼운 흰 띠, 0.11 은 뾰족하게 찢어진다 |
| `_FoamWobble` | 0.30 | 0.55 는 불꽃처럼 뾰족뾰족 |
| `_ColorSteps` | 4 | |

**`_RippleScale` 은 UV 스케일에 종속된다.** Blender 가 물 메시 UV 를 0.22/유닛으로 깔았으므로
지형 치수나 UV 스케일을 바꾸면 이 값도 같이 조정할 것.

- `M_Water_Stream` — 강. 호수 복제 후 흐르는 물로. `_FlowDir (0,-1)`(하류 = UV.y 감소 방향),
  `_FlowSpeed 0.75`, `_RippleScale 9`, `_RippleStretch 2`, 알파 shallow 0.70 / deep 0.92.
  호수보다 불투명하게 둔다 — 강은 얕은 물이 아니라 흐르는 물이다
- `M_Water_Fall` — 폭포. FallStreak 26, FallSpeed 3.2, ColorSteps 7
- `M_Water_Splash` — 낙하 지점. **호수와 같은 색조에 알파만 0.12** 로 둔다. 예전엔 색이 달라
  둥근 판때기가 수면 위에 그대로 비쳐 보였다. 흰 포말만 보이게 하는 게 목적이다
- `M_Water_Rock` — 암반. `M_Rubble_Concrete` 복제 후 어둡게 (기존 콘크리트 잔해가 눈처럼
  하얘서 절벽으로 읽히지 않았다). 원본을 고치면 필드 잔해까지 바뀌므로 복제했다
- `M_Water_Bed` — 호수 바닥

색조는 현재 **선명한 청록**이다 (shallow `(0.00, 0.865, 1.00)`). 아포칼립스 톤에 맞춘 탁한
회녹색으로 내리려면: shallow `(0.34, 0.46, 0.42)`, deep `(0.06, 0.14, 0.17)`,
foam `(0.80, 0.84, 0.80)`, ripple `(0.55, 0.68, 0.64)`.

`물 디오라마 셋업` 은 머티리얼 **에셋을 덮어쓰지 않는다** — 메시에 물려주고 키워드만 맞춘다.
위 튜닝값은 안전하다.

## 씬 배치 — FieldBuilder 가 한다

**손으로 놓지 말 것.** 예전엔 프로토 씬에만 손으로 놓여 있어서 두 가지 사고가 났다:

1. `프로토타입 씬 생성` 은 필드 씬을 열어 그 위에 얹어 저장한다. 물이 필드 씬에 없으면
   **프로토 씬을 다시 만들 때마다 물이 통째로 사라진다.**
2. 씬 뷰에서 드래그하다 위치가 `(-21.43, -0.12, 0.86)` / Y `84.54°` 로 밀려 있었다.
   잔디 평면은 x = -20 에서 끝나는데 암반이 x = -29.5 까지 뻗어 절반이 허공에 떠 있었다.

이제 `FieldBuilder` 가 필드 씬의 `_Water` 아래에 프리팹을 배치한다.

```
WaterPos   (-13, 0, 0)
WaterYaw   180°     ← 필수. FBX 축 변환으로 로컬 -Z 가 절벽이라, 회전하지 않으면
                       절벽이 카메라와 호수 사이에 놓여 호수를 가린다
WaterClear 1.6m     프롭 금지 여유
```

프롭 배치보다 **먼저** 놓고 렌더러 월드 바운즈를 재서 그 사각형 안에는 프롭을 뿌리지 않는다
(`FieldBuilder.PlaceWater`). 실측 금지 영역 `x[-21.3, -4.7] z[-7.5, 9.1]`, 프롭 65개 배치.
예전처럼 손으로 13개를 지웠다가 `필드 생성` 후 되살아나는 일이 없다.

## 충돌 (`ProtoBlocker`)

디오라마 전체 바운즈는 11.3×11.7 이라, 이걸 `_Props` 계층에 넣어 `ProtoObstacles` 에 맡기면
절벽 뒤 빈 공간까지 통째로 막는 큰 상자가 된다. 그래서 막을 부분만 `ProtoBlocker` 로 명시한다.
`물 디오라마 셋업` 이 파트 로컬 바운즈에서 자동 생성해 프리팹에 넣는다.

`WaterSetup.cs` 상단 토글로 켜고 끈다.

| 토글 | 기본 | 블로커 | 모양 | 로컬 center / half |
|---|---|---|---|---|
| `BlockLake` | **false** | `Blocker_Lake` | Ellipse | (0.13, 0.11) / (5.86, 6.06) |
| `BlockCliff` | true | `Blocker_Cliff` | Box | (0.00, −6.05) / (6.65, 1.45) |

**호수는 막지 않는다 — 플레이어가 물에 들어갈 수 있어야 한다는 결정이다.**
막고 싶으면 `BlockLake = true` 로 바꾸고 `물 디오라마 셋업` 을 다시 돌리면 된다.
프리팹 인스턴스라 씬은 자동으로 따라온다(두 씬 다).

`BlockLake` 가 꺼져 있으면 절벽 박스의 z 클립도 건너뛴다 — 겹칠 림 볼륨이 없으니 전체 두께를 쓴다.

### 물에 들어갈 때 알아둘 것

플레이어 y 는 0 고정인데 수면은 0.55, 림 암반 윗면은 0.78 이다. 그래서 물에 들어가면
**캐릭터가 암반을 뚫고 지나가고, 물에 잠긴 것처럼 보이지도 않는다** — 캐릭터는 렌더 큐 4001,
물은 2600 에 `ZWrite Off` 라 캐릭터가 항상 물 위에 그려진다.
잠수 느낌이 필요하면 캐릭터 큐를 물보다 앞으로 내리거나, 수면에서 캐릭터를 잘라내는 처리가 따로 필요하다.

- **호수를 막을 거라면 타원이어야 한다.** 둥근 사각형을 박스로 덮으면 네 모서리에 1m 넘는
  보이지 않는 벽이 생긴다. 타원은 축에서 약간 넉넉하고 모서리에서 약간 모자라 오차가
  양쪽 0.2~0.4m 로 갈린다 (`WaterSetup.LakeFit = 1.04`).
- **절벽 박스는 림과 겹치는 부분을 잘라낸다.** 두 볼륨이 겹치면 밀어내기가 서로를 되받아쳐
  플레이어가 지오메트리 안에 갇힌다. `WaterSetup` 이 림 바운즈에서 z 범위를 클립한다.

검증 (에디터 실측, `BlockLake=false` 기준): 호수 중심에서 이동량 **0.0000m**,
수면 격자 241점 전부 자유(막힘 0) — 물에 들어갈 수 있다 /
절벽 뒤에서 접근하면 z = 7.85 에서 정지 (뒷면 7.50 + 플레이어 반지름 0.35) — 절벽은 계속 막는다.

## 미해결

- **호수가 서쪽 플레이 공간을 크게 먹는다.** 막히는 지름이 약 12.4m 인데 아레나는 반경 19다.
  호수 서쪽 가장자리(-19.2)와 아레나 클램프(-19)가 사실상 붙어 있어 서쪽으로 돌아갈 길이 없다.
  장애물로 의도한 것이면 그대로 두고, 아니면 `WaterPos` 를 동쪽(예: -11)으로 옮길 것.
- **필드 경계 밖이 그냥 하늘이다.** 물과 무관한 기존 문제지만, 물이 서쪽 끝에 있어 호수 근처에서
  플레이하면 눈에 띈다. 원경 배경(빌보드 산·건물)이 필요하다.
- 물이 정점 컬러에 의존하므로 **지형을 손으로 편집하면 깊이·포말 정보가 어긋난다.**
  형태를 바꿀 때는 Blender 스크립트 치수를 고쳐 다시 생성할 것.
- Depth Texture 를 켤 여유가 생기면, 셰이더에 `shader_feature` 경로를 추가해 정점 컬러를
  다시 굽지 않고도 자동 교차 포말로 갈 수 있다 (현재 미구현).
