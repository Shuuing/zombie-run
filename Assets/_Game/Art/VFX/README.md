## 쓰는 법

```csharp
ProtoLightningStrike.Play(player.transform.position);   // 좌표는 '발밑'
```

씬 배선이 필요 없다 — 처음 부를 때 스스로 생성되고 스프라이트·셰이더·프리팹도 코드가 잡는다
(`ProtoLevelUpBeam`·`ProtoAudio` 와 같은 방식). 현재 `ProtoCharacterSwitcher.Select()` 가 부른다.

## 왜 두 겹인가

번개 줄기는 **플립북**, 지면 타격은 **파티클**이다. 각자 못 하는 게 정확히 반대라서 나눴다.

- 가지치는 번개는 절차적으로 못 만든다. 노이즈 지그재그는 굵기가 일정해서 "전선"으로 보인다.
- 반대로 지면 섬광을 플립북에 그려 넣으면 **세로 빌보드에 그려져서 바닥에 눕지 않는다.**
  카메라 피치가 37°라 부채꼴이 공중에 뜬 것처럼 읽혔다. 그래서 링만 진짜 지면 메시로 뺐다.

지면 프리팹은 줄기가 바닥에 닿는 프레임(`impactFrame`, 기본 3 → 0.10초)에 한 번 터진다.

`.anim` 클립은 런타임 경로에서 **쓰지 않는다.** Animator 는 `Time.timeScale` 을 따르므로
게임이 멈춘 상태(레벨업 카드)에서 교체가 일어나면 번개가 얼어붙는다. 스크립트가
`ProtoConfig.UnscaledDelta` 로 직접 프레임을 넘긴다. 클립은 Timeline·컷신용으로 남겨 둔 것이다.

## 원본을 다시 구울 때 (`ArtSource/VFX/bake_lightning.py`)

원본 `lightning_01.png` (AI 컨택트시트) 를 그대로 쓰면 안 된다. 이유가 셋이다.

1. **알파가 0/255 이진값이고, 눈에 보이는 파란 글로우는 전부 알파 0 영역의 RGB 에만 있다.**
   그대로 임포트하면 톱니 난 흰 막대만 남는다. 배경색 `(5,32,61)` 대비 RGB 밝기에서 알파를
   복원하고 색을 언믹스해야 원본 프리뷰대로 나온다.
2. **셀마다 잘린 양이 다르다.** 격자는 600px 간격인데 바깥에 흰 여백이 있어서 1열은 왼쪽 76px,
   4열은 오른쪽 104px, 4행은 아래 52px 이 없다. 셀을 각각 리샘플하면 번개 축이 어긋나므로
   공통 캔버스에 **오프셋 붙여넣기**로 맞춘다.
3. **마지막 칸에 생성 AI 워터마크(회색 4각 반짝이)가 있다.** 원본 알파로는 안 보이지만 알파를
   복원하면 튀어나온다. 스크립트의 `KILL_BELOW` 가 잘라낸다.

## 지면 프리팹은 NamuFX 팩에 의존한다

`FX_LightningGround.prefab` 은 `Assets/NamuFX/AoeExplosions vol2` 의 `explosion_lightning` 에서
쓸 부품 둘(`lightning01` = Shockwave02 메시 링, `sparks`)만 떼어낸 것이다. 그래서 **팩을 지우면
이 프리팹이 깨진다.** `ProtoLightningStrike.BuildGround()` 가 그 경우 경고 한 줄만 남기고
번개 줄기만으로 계속 가게 해 뒀다 — 연출 하나 때문에 캐릭터 교체가 막히면 안 되기 때문이다.

떼어내면서 고친 것:

- **팩 머티리얼은 복사해서 고쳤다** (`M_LightningRing.mat`). 원본을 직접 고치면 팩 자기 프리팹이
  같이 물들고, 팩을 다시 임포트하면 날아간다.
- **알파 블렌딩(5,10) → 가법(5,1).** 원본 그라디언트가 검붉은색이라 밝은 아스팔트 위에서
  전기가 아니라 **그을음**으로 읽혔다. 색도 흰색→하늘색으로 갈았다.
- **`scalingMode` 을 Local → Hierarchy 로.** Local 이면 각 시스템이 자기 스케일만 봐서
  루트를 줄여도 자식이 안 따라온다 (팩 원본이 24m 짜리인데 이 게임 화면엔 지면이 10m 뿐이다).
- **불똥 퍼짐은 스케일로 안 잡힌다.** `velocityOverLifetime`·`limitVelocity` 가 월드 단위라
  배율을 안 탄다. 그 모듈을 끄고 `startSpeed`·`gravityModifier`(2.6)·콘 형태로 직접 박았다.
  중력을 준 게 핵심 — 튀어오른 불똥이 도로로 되떨어져야 '지면 타격'으로 읽힌다.

## 줄기 길이는 런타임이 정한다 (상수로 박지 마라)

번개는 화면 **바깥**에서 내려와야 한다. 화면 안에서 끝나면 "하늘에서 내려온" 게 아니라
"허공에서 생긴" 것으로 보인다. 그런데 **필요한 월드 높이는 카메라가 정한다**:

| 카메라 | 화면 꼭대기 (캐릭터 발밑 기준) |
|---|---|
| `ProtoCameraFollow` 각도1 (피치 58°, 거리 17.76m) | **7.97m** |
| 각도2 (오프셋 0,6.67,-9.41 / 피치 37.3°) | **3.92m** |

두 배 넘게 차이난다. 상수로 박으면 한쪽에서 반드시 틀린다.
(화면비는 영향 없다 — 유니티 카메라는 **수직** FOV 가 고정이라 21:9 든 9:19.5 든 세로 화각이 같다.
다만 계산은 `cam.projectionMatrix` 를 직접 읽으므로, 나중에 가로 FOV 유지 방식으로 바꿔도 따라간다.)

### 그래서 메시를 쓴다

`ProtoLightningStrike` 는 SpriteRenderer 가 아니라 **가로 3줄로 나눈 쿼드 메시**를 만든다.

```
 v=1      ┌──────┐  ← 여기까지 k 배로 늘어난다 (화면 밖까지)
          │ 줄기 │
 v=SeamV  ├──────┤  ← 이음매 (0.3913)
          │ 섬광 │     이 아래는 항상 1:1 — 배율과 무관
 v=0      └──────┘
```

`Play()` 때 `ScreenTopHeight()` 로 "이 카메라에서 화면 위로 나가는 높이"를 풀고
(뷰포트 y=1 은 `clipY == clipW` 이고 둘 다 높이의 1차식이라 두 점이면 반복 없이 정확히 풀린다),
거기 `screenMargin`(1.15)을 곱한 값에 맞춰 윗줄만 늘린다. 배율이 1 이든 6 이든 **섬광은 안 찌그러진다.**

- 배율은 재생 시작에 **한 번만** 잡는다. 매 프레임 다시 재면 카메라가 따라오는 동안 줄기 길이가
  늘었다 줄었다 해서 숨 쉬는 것처럼 보인다.
- `SeamV` 는 굽는 스크립트가 출력하는 값이다. **섬광 몸통 전체가 이 아래 들어가야 한다** —
  올리면 섬광 윗부분이 늘어나 찌그러진다.
- `.anim` 클립은 SpriteRenderer 용이라 이 화면 맞춤이 안 걸린다. Timeline 에서 쓸 때는
  카메라에 맞춰 직접 늘려야 한다.

## 임포트 설정에서 건드리지 말 것

- **1024×1024 (2의 거듭제곱)**. 처음에 1024×960 으로 구웠더니 유니티 Android 압축기가 NPOT 라며
  통째로 무시하고 RGBA32 로 남겼다 (5MB). POT 로 맞추니 ASTC 6×6 = 1.2MB.
- **피벗 (0.5, 0.1452)** = 착탄 프레임들에서 실측한 지면 섬광 줄(`GROUND_V`). 그래서
  `transform.position` 에 발밑 좌표를 그대로 넣으면 맞는다. 높이를 따로 보정하지 마라.
  런타임 메시도 이 피벗에서 지면선을 읽으므로, 굽는 설정을 바꾸면 **출력된 GROUND_V·SEAM_V 를
  유니티 슬라이스와 `ProtoLightningStrike.SeamV` 에 그대로 옮겨 적어라.**
- **셀 안쪽 2px 투명 여백**. 없애면 밉맵/바이리니어가 아틀라스 이웃 프레임을 끌어온다.
- **PPU 60** → 스프라이트 4.27m (번개 실효 높이 4.0m). 캐릭터 1.7m 기준으로 잡은 값이다.

# 화염 제트 스프라이트 (`T_FlameJet` / `M_FlameSprite`)

화염방사기의 불을 **쿼드 한 장 + 15칸 플립북**으로 그리는 두 번째 구현이다.
기존 파티클 판(`ProtoFlameCone`)은 **지우지 않았다** — 옵션에서 서로 바꿔 가며 비교한다.

- 굽기: `ArtSource/VFX/bake_flamejet.py`
- 아틀라스: `Assets/_Game/Resources/VFX/T_FlameJet.png` (2048×1024 로 구워 1024×512 로 임포트,
  ASTC 6×6, **밉맵 없음**, 4×4 격자 중 15칸 사용)
- 구동: `ProtoFlameSprite` / 셰이더 `Proto/FlameSprite`

## 원본 시트를 그대로 자르면 안 되는 이유

원본은 3×5 컨택트 시트인데 작가가 **칸 안에서 가운데 맞춤**으로 그렸다.
점화 프레임은 x=252 에서 시작하고 지속 프레임은 x=9 에서 시작한다.
그대로 재생하면 불이 총구에서 떨어진 허공에 떴다가 슬금슬금 총구 쪽으로 밀려온다.

굽는 스크립트가 **각 칸의 내용 왼쪽 끝(불의 뿌리)을 공통 노즐 위치에 맞춘다.**
세로는 반대로 **모든 칸에 같은 y 구간**을 쓴다 — 세로까지 각자 맞추면 불이 위아래로 튄다.
그래서 프레임이 갈수록 불꽃이 살짝 떠오르는 원본의 움직임은 그대로 남는다.

결과적으로 **런타임에서 길이를 만질 필요가 없다.** 점화 프레임이 짧은 것은 그림 자체가
짧아서지 쿼드를 줄여서가 아니다 (프레임별 뻗은 길이 0.23 → 1.00 → 0.81).

## 프레임 구간

| 구간 | 프레임 | 하는 일 |
|---|---|---|
| 점화 | 0–5 | 연기 → 불티 → 작은 불 → 앞으로 뻗음. `igniteSpeed` 1.6배로 빨리 넘긴다 |
| 지속 | 5–10 | 여기만 순환한다. 되감기는 지점도 셰이더가 두 프레임을 섞어 팝이 없다 |
| 소화 | 11–14 | 사그라들고 연기만 남는다 |

## 건드리지 말 것

- **밉맵 끄기.** 플립북 아틀라스는 밉 레벨이 올라가면 옆 칸이 번져 들어와 엉뚱한 프레임이
  섞인다. 카메라 거리가 고정된 게임이라 축소 앨리어싱은 걱정거리가 아니다.
- **칸 가장자리 4px 여백**(`PAD`). 바이리니어가 옆 칸을 물지 않게 한다.
- **`NozzleV = 0.5466`** 는 굽는 스크립트가 출력하는 값이다. 다시 구우면 출력된 값을
  `ProtoFlameSprite.NozzleV` 에 그대로 옮겨 적어라. 안 맞추면 불이 총구 위아래로 어긋난다.
- **`_ZTest` 기본값 Always.** 제트는 노면에 거의 붙어 누워 있어서 깊이 테스트를 켜면
  도로가 불의 아랫부분을 직선으로 잘라 먹는다. 가법 블렌딩이라 위에 덧그려도 밝아지기만 한다.

고친 뒤로는 칠하는 화소가 13배 차이 난다 — 파티클은 겹쳐 그리는 양이 곧 비용이라
두껍게 하려면 그만큼 내야 하고, 플립북은 겹침이 항상 1배다.

**그래도 그림은 파티클 쪽으로 정했다**(2026-09-18). 이 판은 지우지 않고 남겨 둔다 —
A54 에서 화염이 프레임을 갉아먹으면 칠하는 화소가 13분의 1인 이쪽이 대안이다.

> `ProtoRainFx` 주석에 "화염은 채우기 지배라 쿼드로 바꿔도 안 싸진다"고 적어 뒀던 예측은
> **틀렸다.** 파티클의 채우기는 대부분 입자끼리 겹쳐 그리는 양이고, 플립북은 그 겹침을
> 1배로 눌러 채우기 자체를 줄인다.
